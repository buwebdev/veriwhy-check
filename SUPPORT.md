# Support

Author and maintainer: Richard Krasso

## Students

Start with these commands:

```text
veriwhy-check doctor
veriwhy-check help
veriwhy-check list WEB-425
```

If a check does not finish, first copy the complete error message and run `veriwhy-check doctor`. If
the problem remains, open a
[GitHub bug report](https://github.com/buwebdev/veriwhy-check/issues/new?template=bug_report.yml).
The form explains exactly what to provide.

Questions about grades, deadlines, or assignment interpretation belong in the course's normal
instructor-support channel. VeriWhy Check reports practice results; it does not assign the official
grade.

## Bug Reports

Use the repository's bug-report form. Include:

- the VeriWhy Check version;
- operating system;
- course and assignment identifier;
- the command entered;
- the sanitized error message; and
- whether `veriwhy-check doctor` reports an action needed.

An issue is a request for review, not an automatic promise that the application will change. The
maintainer will reproduce and evaluate the report, then decide whether it is a VeriWhy Check defect,
a project setup problem, an assignment question, an unsupported system, or a feature request.
Confirmed product defects will be prioritized according to their effect and available support.

Public issues must never contain assignment source, screenshots containing private information,
student names, passwords, access tokens, private repository links, or other credentials. A small
sanitized error excerpt is appropriate. Security or privacy concerns must not be filed as public
bugs.

Security or privacy concerns must follow [SECURITY.md](docs/SECURITY.md).
